Run instructions (updated 2026-06-08)

Admin (UI / smoke-test)

From the workspace root, run the admin app:

```powershell
dotnet run --project IDK2/AdminApp.csproj
```

Run the automated smoke test (writes `smoke_report.txt`):

```powershell
dotnet run --project IDK2/AdminApp.csproj -- smoketest
```

Run the built output directly (after building in Debug):

```powershell
dotnet IDK2\bin\Debug\net8.0-windows\AdminApp.dll
```

Applicant (console / UI)

Console mode:

```powershell
dotnet run --project IDk/ApplicantApp.csproj
```

Open the WinForms UI:

```powershell
dotnet run --project IDk/ApplicantApp.csproj -- ui
```

Prerequisites and PowerShell troubleshooting

- .NET SDK 8.0 or newer is required for the UI builds. Verify with:

```powershell
dotnet --info
```

- UI apps must be run on Windows desktop (interactive session).

- PowerShell notes: some build or helper scripts may invoke `powershell` (Windows PowerShell) or `pwsh` (PowerShell 7+). If you installed PowerShell 7 (`pwsh`) but the workspace still complains about a missing or out-of-date PowerShell, try the steps below.

1) Restart VS Code and open a new integrated terminal (required for PATH changes to take effect).

2) Check what the system finds:

```powershell
pwsh --version
powershell -NoProfile -Command "$PSVersionTable.PSVersion"
where pwsh
where powershell
```

3) If `powershell` is not found or a script requires `powershell` to point at PowerShell 7, you can add a lightweight wrapper so `powershell` forwards to `pwsh` when available. Create a file at `%USERPROFILE%\bin\powershell.cmd` with the following content:

```powershell
@echo off
IF EXIST "%ProgramFiles%\PowerShell\7\pwsh.exe" (
	"%ProgramFiles%\PowerShell\7\pwsh.exe" %*
) ELSE IF EXIST "%ProgramFiles(x86)%\PowerShell\7\pwsh.exe" (
	"%ProgramFiles(x86)%\PowerShell\7\pwsh.exe" %*
) ELSE (
	"%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe" %*
)
```

Then add `%USERPROFILE%\bin` to your user PATH (Windows Settings → Environment Variables), or run this once (you will need to restart terminals/VS Code afterwards):

```powershell
setx PATH "%USERPROFILE%\bin;%PATH%"
```

Note: This workspace includes a convenience wrapper at `C:\Users\Ioan\bin\powershell.cmd` that can help if `powershell` is not resolving to a usable shell.

Other notes

- Build-time warnings about nullable fields are usually warnings only and often do not block running the app.
- To stop a running app: press Ctrl+C in the terminal.
